### W8 的细节

1. **构造函数里的虚调用**：C++ 在基类构造期间调用 `setPos(0,0,0)` 只会调到 `Entity::setPos`
   （子类重写不参与）；TS 以前用 `this.setPos`，会在构造时派发到子类。改为
   `Entity.prototype.setPos.call(this, 0, 0, 0)`。`_init` 本身不是 virtual，同样改成
   `Entity.prototype._init.call`，避免 JS 的动态派发。
2. **float 字段与形参**：`bbWidth = f(0.6)`、`bbHeight = f(1.8)`；`setSize` / `setRot` / `setPos` /
   `moveTo` / `turn` / `interpolateTurn` / `lerpMotion` 的形参先转 float，算术每步 `f()`。
3. **距离与推挤**：`distanceTo` / `distanceToSqr` 的减法、平方、求和逐步 float；`push` 的
   `sqrt`、除法、`0.05f`、`1 - pushthrough` 逐步 float。比较常量 `0.01f` 写成 `f(0.01)`——
   float 的 0.009999999776… 与 double 的 0.01 在边界上会得出不同结果。
4. **其它**：`resetPos` 的 `y += 1` 按 float；`getPickRadius` 返回 `f(0.1)`；
   `getShadowHeightOffs` 返回 `f(bbHeight / 2)`；`intersects` 改用 `AABB.intersectsXYZ`
   （与 C++ 6 参重载逐参数转 float 相同）。

### 顺带修正（审核暴露的）

`Entity.setPos` 修正后，`tests/unit/client/particle-engine.test.ts` 的一条期望失败：
C++ 的 `ParticleEngine::crack` 是 `float yp = y + tile->yy0 - r;`（`(y + yy0) - r` 两个 float
步骤），而测试写的是 TS 旧的 double 表达式。按方案第 6 节的例外处理：**期望值本身来自 TS，
C++ 源码可证**。已把 `ParticleEngine.crack` 的六个 face 分支改为分步 `f()`，测试期望同步改成
f 链，并在提交说明里写明。
