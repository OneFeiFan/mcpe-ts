# S3 方块类移植单

本轮基础设施（Tile 基类、注册表、Item 骨架、Level 前向声明等）已经就位。16 个方块类中，有非 1:1 决定的 10 个（外加它们的两个基类）也已经移植并测试过，**剩下 5 个：StoneTile、DirtTile、GrassTile、InvisibleTile、TopSnowTile**，都是简单的 1:1。下面的表格保留全部 16 个类的说明，方便对照。

## 完成顺序与完成标志

1. 按下表移植剩下的 5 个类，每个类一个文件，放在 `packages/world/src/level/tile/`，文件名与类名和 C++ 相同。
2. 从 `S3-待方块类就位后加入.zip` 里取出两个文件，按原路径放进仓库：
   - `packages/world/src/level/tile/TileInclude.ts`
   - `tests/unit/world/tile-registry.test.ts`
3. 在 `packages/world/src/index.ts` 末尾导出 `TileInclude.js` 与这 5 个类。
4. 运行 `pnpm typecheck` 和 `pnpm test` 确认全绿，其中 `tile-registry.test.ts` 就是 S3 的验收。
5. 运行 `pnpm ledger Tile` 核对条数：应为 76 条（`Tile.ts` 的 72 条，加上 `FireTile.ts` 构造函数里的 4 条），这 5 个类不会再增加。

## 通用规则

- **C++ 的重载 virtual。** `getTexture`、`mayPick`、`mayPlace`、`getSignal` 这四组，子类重写 C++ 的哪个重载，就重写对应后缀的方法；同名的分派方法不要重写。

  | C++ 重载 | TS 方法 |
  |---|---|
  | `getTexture(int face)` | `getTexture$1` |
  | `getTexture(int face, int data)` | `getTexture$2` |
  | `getTexture(LevelSource*, x, y, z, face)` | `getTexture$5` |
  | `mayPick()` | `mayPick$0` |
  | `mayPick(int data, bool liquid)` | `mayPick$2` |
  | `mayPlace(level, x, y, z)` | `mayPlace$4` |
  | `mayPlace(level, x, y, z, face)` | `mayPlace$5` |

  - C++ 里显式调用基类的 `Tile::getTexture(face, data)`，写成 `super.getTexture$2(face, data)`。
  - C++ 里调用自己的 `getTexture(face)`，可以写成 `this.getTexture(face)`（分派方法），也可以直接写 `this.getTexture$1(face)`，效果相同。
- **OMIT。** 签名含 Player、Entity、Mob、ItemInstance 的方法不写，`spawnResources`、`popResource` 也不写。在原位置留一行标记：`// OMIT(系统): 签名  文件:行`。下表已经列出每个类要 OMIT 的方法。
- **未注册的方块。** `Tile.xxx` 如果对应的是 initTiles 里 DEFERRED 的那一行，它就是一个哨兵对象，任何访问都会抛出写明字段名的错误（相当于 C++ 的 NULL）。
  - 只拿来**比较 id** 的地方（`getTile(...) == Tile::xxx->id`），写成 `=== idOf(Tile.xxx)` 并标 `ADAPTED(DeferredTile)`：未注册时返回 -1，按“不等于”处理，已注册后与 `.id` 完全相同。已移植的 10 个类里共有 4 处。
  - 其他用途（把 id 写进世界、读纹理等）照 1:1 直接写 `.id`、`.tex`，未注册时照常报错。
  - 访问发生在构造函数里的，必须切掉，否则 `initTiles` 当场报错。只有 FireTile 有这种情况。
  - 访问发生在 tick、流动、燃烧等运行时路径上的，照 1:1 保留，并在旁边写一行 `// 依赖未注册：xxx` 提醒。demo 里的平坦世界走不到这些路径；以后接入世界生成时，要么移植对应的方块，要么把那一行标成 ADAPTED 改写。
- **C++ 的嵌套类型。** `Tile::SoundType`、`Item::Tier`、`Biome::MobList`、`Biome::MobSpawnerData`、`PerfTimer::ResultField`、`WeighedRandom::WeighedRandomItem` 在 TS 里照原样写成 `Tile.SoundType`、`Biome.MobList` 等：作类型用时来自同名命名空间里的类型别名，作值用（`new`、`instanceof`）时来自类上的同名静态属性。以后遇到新的嵌套类型，照 `Biome.ts` 末尾的写法补上即可。
- **Level。** 用到的 Level 成员已经全部在 `Level.ts` 的前向声明接口里（按 C++ 签名，已去掉 OMIT 方法用到的）。如果发现缺了，就按 Level.h 的签名补进接口。
- **构造函数重载。** DirectionalTile 有两个构造函数，写法照 `Tile` 的构造函数：重载签名，加上按参数类型分派。
- **C++ 的名字遮蔽。** BedTile 新增了无参的 `setShape()`，遮蔽了 Tile 的 6 参数版本。TS 里只能有一个 `setShape`，写成两个重载：无参时设床的形状，有参时转给 `super.setShape`（见 `BedTile.ts`）。
- **init() 会重写 lightBlock。** initTiles 在构造之后调用 `init()`，它按 `isSolidRender()` 把 `lightBlock` 重新设成 255 或 0，所以构造函数里的 `setLightBlock(255)` 对半块台阶和耕地不起作用。C++ 的顺序完全一样，这两个方块在分支里都不挡光，照原样保留。
- **数值。** 方块逻辑属于"结构一致，数值放宽"，不用做 `Math.fround`。整数运算照常写 `| 0`。
- **不要翻译的 include。** `GrassTile.cpp` include 了 `client/Minecraft.h` 和 `ItemEntity.h`，都没有用到，不要翻成 import。

待移植的 5 个类要注意的地方：

- **TopSnowTile。** 手册初版的方块清单里没有它，这次补上了。原因是 `Tile.shouldRenderFace` 里有 `t.id === Tile.topSnow.id`：只要一个方块上面还有方块，渲染它的顶面时就会读到 topSnow，不注册就报错。`playerDestroy` 要 OMIT（Player、ItemEntity、`Item::snowBall`）。
- **GrassTile。** `getColor` 在 `GrassColor.useTint` 为 false 时返回 0x339933（分支的默认设置）；为 true 时经 `level.getBiomeSource()` 取温度和降水，这部分已经在 `BiomeSource` 的前向声明里。`GrassTile.cpp` 里 include 的 `client/Minecraft.h` 与 `ItemEntity.h` 都没有用到，不要翻译。
- **InvisibleTile、StoneTile、DirtTile。** 没有特殊之处。

已移植的类里值得知道的：LiquidTileDynamic 的 `isWaterBlocking` 每次液体流动都会执行，原本会碰到 4 个未注册方块，已改用 `idOf`，接入世界生成后水也能正常流动；熔岩源遇水会写入 `Tile.obsidian.id`（未注册，会报错），接入世界生成前要先移植黑曜石。
