# 审核报告

对 2026-10-09 整理后的版本做的一次全面审核：**运行层面**（与原版并排对比）和**代码层面**（行为是否与原版一致、继承与重载是否保持 C++ 语义、风格是否统一、性能热点）。
本报告只记录发现，不改代码；用户看过之后再分批修。状态一栏：**待修**、**保留**（原版怪癖或原版 bug，照原样）、**无影响**（核对后确认与原版一致）、**待核**（还没查完）。

## 一、方法

### 运行层面：原版与 TS 版并排对比

- 原版用 `tools/original/build.sh` 编成 Linux 桌面版（GLFW + X11），在 Xvfb 里用软件渲染运行；窗口 854×480（原版默认）。
- 同一套操作步骤分别驱动两边：原版用 xdotool（`tools/original/compare/drive_original.py`），TS 版用 Playwright（`drive_ts.py`），坐标相同。
- 截图逐像素比较（`cmp.py`）：统计每个像素三通道差值的灰度 ≤ 8 的比例，并拼成并排图人工看。
- 原版能正常启动，启动日志与 TS 版逐行一致（四行 `Missing category for tile …`、`IS TOUCHSCREEN? 1`、`numBuffers: 26136`、`Reloading-options`）。

### 代码层面

- `tools/audit/`：从 C++ 头文件提取 711 个类（基类、方法、是否 virtual、重载、默认参数），从 TS 提取 519 个类（extends、方法、override、构造函数与方法体里的 `this.方法()` 调用），对两边都有的 489 个类逐个比较。脚本给出候选，**每条都人工对照 C++ 调用点确认**。
- 按值语义扫描：带值类型参数（`ItemInstance`、`Vec3`、`AABB`、`Pos` 等）的方法里，直接 `this.x = 参数` 存引用的地方。
- 风格统计：文件头、截断写法、重载分派写法、类型逃逸。

第一次对比进世界的画面只有 18.69% 一致，查明两处都不是移植错误，而是**按帧计算的状态**在两边帧率不同时自然不同：

- **远处海面的断层**：TS 版的区块还没重建完（等了 240 秒仍有 393 个待重建），原版已经全部建好。

结论：以后做运行对比，按帧推进的状态（暗角、区块重建队列、物品名渐隐等）要先对齐再比较。

## 六、替代实现与存档格式

- 存档格式**维持 NBT**（用户决定）：它是原版 level.dat、区块、实体、玩家数据的格式，换掉会失去与原版存档的兼容、丢失数字类型（byte / short / int / long / float / double），并让逐字节比较的黄金样本失效。
- 原版存档没有压缩；贴图解码、UTF-8 编码已经用浏览器自带的功能；随机数必须与 C++ 逐位一致。目前没有发现“手写了但有现成实现可替换”的东西。
