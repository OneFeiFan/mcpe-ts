# 移植规范

把 MCPE 0.6.1 的 C++ 源码逐个函数移植成 TypeScript 时必须遵守的规则。来源是最早的施工单（修订版 1–10，原文在 git 历史里），这里只留至今仍然有效的部分。

判断对错的依据只有三个：**参考 C++ 源码**（用 `tools/porting/clean.py` 展开 `#ifdef` 之后的那一份）、**黄金样本**、**浏览器实测**。

## R1 路径与包

- 镜像 C++ 目录：`src/world/level/tile/Tile.h` → `packages/world/src/level/tile/Tile.ts`，类名、文件名不改。
- 依赖只能单向：`platform → util → core → nbt / locale → world → client → apps/web`。`world` 不得依赖 `client` 与 DOM。

## R2 文件类别与台账标记

- **1:1**：逐函数照抄，只允许 TS 语法层面的机械改写（重载 → 参数分派、运算符 → `equals` / `lessThan`、按值 → 复制）。
- **ADAPTED**：有意偏离 C++，每处写明原因。**NEW**：C++ 里没有的文件（平台层、测试辅助等）。
- 缺口一律登记，原句不删：

```ts
// DEFERRED(系统): <原 C++ 语句，原样保留，恢复时直接还原>
// OMIT(系统): 函数签名  <C++ 文件:行>
// ADAPTED(原因): 说明
```

- `node tools/ledger.mjs`（`pnpm ledger`）按“标记(系统)”汇总条数；`pnpm ledger Network` 列出某个系统的全部条目。
- 数标记必须用台账那条严格正则；宽松的 `grep` 会把正文里提到标记的说明文字也算进去。

## R3 函数三态

- 每个函数只能是 **PORT**（照移植）、**PORT-CUT**（移植，个别语句 DEFERRED）、**OMIT**（不移植）之一，**不写桩函数体**。
- virtual 函数在整个继承链上一起 OMIT；被 OMIT 的函数若有已移植代码调用，在调用处标 DEFERRED。
- 析构函数不移植；网页版构建没选中的 `#if` 分支不移植也不登记。
- 必须存在、但唯一实现依赖未移植系统的函数：保留签名，原句写成 DEFERRED，函数体抛出写明原因的错误，**不返回假值**。
- C++ 构造函数没有初始化的字段（未定义值）取 0 或 false，并在字段旁注明。**不复刻未定义行为**；黄金样本里把这类字段标 `uninit`，不比较。

## R4 数值：三档规则

不是每一处都要与 C++ 逐位一致，按“差异能不能被察觉、会不会累积”分三档：

| 档位               | 范围                                                                                                                                                                                   | 要求                                                 |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| 必须一致           | 种子 → 世界的整条链（Random、噪声、BiomeSource、群系选择、`LevelChunk.getRandom`、地形与地物生成、文字种子的 `hashCode` / `stringTrim`）；存档格式；网络协议；寻路与生物 AI 的随机序列 | 逐位一致，用黄金样本核对                             |
| 结构一致，数值放宽 | 物理、光照传播、计划刻、方块逻辑、昼夜时间                                                                                                                                             | 算法、常量、调用顺序与 C++ 相同；可以不做 float 舍入 |
| 自由处理           | 渲染数学、GUI、粒子、声音、输入平滑、PerfTimer、日志、平台层                                                                                                                           | 怎么方便怎么写                                       |

例外：输出被黄金样本**逐位钉住**的渲染代码（比如模型几何的 UV）不享受第三档豁免，照第一档写。

第一档的写法：

| C++                                                 | TS                                       | 说明                                                                                         |
| --------------------------------------------------- | ---------------------------------------- | -------------------------------------------------------------------------------------------- |
| float 运算                                          | 每一步 `Math.fround`（仓库里简写 `f()`） | 全程 double 最后才舍入是错的                                                                 |
| float 常量 `0.95f`                                  | `f(0.95)`                                | **判据是 C++ 原句有没有 `f` 后缀**，不是“这个数精不精确”；没有后缀的是 double 字面量，不能包 |
| int 与 float 混算                                   | int 先 `f(x)`                            | C++ 先把 int 转成 float                                                                      |
| float 形参                                          | 入口处 `f(x)`                            | 调用方传入的 double 在形参处已被舍入                                                         |
| `(int)` 强转                                        | `f2i(x)` / `Math.trunc`                  | 越界或 NaN 得 −2147483648（x86）；黄金样本在 x86-64 上生成                                   |
| int 乘法、加减                                      | `Math.imul`、`\| 0`                      | `long` 乘法只用低 32 位时同样写 `Math.imul`                                                  |
| 整数除法                                            | `Math.trunc(a / b)`                      | 用 `python tools/porting/divs.py` 逐条判断，左操作数是 float 的不是整数除法                  |
| C 库 `sin` / `cos` / `sqrt` / `pow`（不带 `Mth::`） | `Math.sin` 等，按 double 算              | 与 `Mth.sin`（查表）结果不同，按 C++ 原文对应；查表函数要先 `Mth.initMth()`                  |
| `Mth::floor(float)`                                 | 参数先 `f()`                             | 它只有 float 版，double 实参先被转成 float                                                   |
| 不带 `Mth::` 的 `abs(float)`                        | float 版本                               | G17-2 的 treeShape 表确认过，不是先截成整数的 `::abs(int)`                                   |

## R5 值语义

- C++ 按值传递或拷贝的 `Vec3`、`TilePos`、`AABB`、`HitResult`、`ItemInstance`、结构体，在 TS 里是引用：赋值时复制（`new ItemInstance(x)`、`clone()`、`assign()`），**不要共享引用**。
- 成员对象（`Minecraft` 的 `timer`、`options`、`gui`……）在构造函数里按 C++ 的成员声明顺序创建。

## R6 容器

- `std::set` / `std::map` 的有序遍历要保留：用 `Map` 时遍历前按键排序。
- `std::set<TickNextTickData>` 按 `(delay, c)` 有序，`c` 每次递增，`find()` 的去重分支永远不命中——照原样，不要“修”。
- `Map`、`Set` 的键用打包整数或字符串，不用对象；`std::vector::erase` 的语义逐一保留（边遍历边删要 `splice(i, 1); i--`）。

## R7 静态注册与初始化顺序

- 基类需要 `new` 子类的注册表（`Tile`、`Item`、`Material`、`Tag`、`TileEntity`）由 `XInclude.ts` 注入子类构造器：基类文件只 `import type` 子类。
- 初始化顺序照 `NinecraftApp::init`：`Mth → Material → MobCategory → Tile → Item → Biome → TileEntity`。

## R8 导入

- 包内只 import 具体文件，不 import 自己的入口文件；纯类型一律 `import type`。
- C++ 里没用到的 `#include` 不翻译（否则会让 `world` 反向依赖 `client`）。
- **不要用 `declare` 代替 import**：能过类型检查，运行时不存在。

## R9 黄金样本

- C++ harness 放 `tools/golden/`，产物放 `fixtures/golden/` 并提交，开发机不需要编译器。
- 必须在 x86-64 上生成。详见 `docs/验证方法.md`。

## R10 C++ 重载

同名方法在 TS 里只能有一个实现：

- **情形 A**：短的重载只是用常量转调长的那个（且没有子类单独重写短的）——合并成带默认参数的一个方法，例如 `spawnResources(level, x, y, z, data, odds = 1)`。
- **情形 B**：其余情况——基类保留原名作为分派入口，每个 C++ 重载对应一个按区分参数命名的实现方法；子类重写 C++ 的哪个重载，就重写对应的实现方法，分派入口本身不在子类里重写。
- 参数个数相同、只靠 int / float / char 区分的重载（JS 分不出来）：最常用的保留原名，其余改名并标 `ADAPTED(Cpp)`。例如 `Tesselator.color`（float 版）与 `colorInt`、`colorChar`——**照字面抄 `t.color(255, 255, 255, 255)` 是错的**，C++ 那里选中的是 int 版。
- 引用输出参数改为返回元组（`Screen.toGUICoordinate`、`queryHoldTime` 等）。
- 无参的 `init()`：`App` → `initApp`、`Dimension` → `initDimension`、`Screen` 子类 → `initScreen`。
- 已有的命名对照：`getTexture → getTextureForFace / getTextureForData / getTextureAt`、`mayPlace → mayPlaceAt / mayPlaceOnFace`、`useOn → useOnWithoutPlayer / useOnByPlayer`、`Level::tick(Entity*) → tickEntity`、`Inventory::removeItem(const ItemInstance*) → removeItemInstance`、`CraftingContainer::getItem(x, y) → getItemAt`、`EntityRenderDispatcher::render(entity, …) → renderAt`、`ItemRenderer::renderGuiItem(…, w, h, fancy) → renderGuiItemSized`、`renderGuiItemDecorations(item, x, y) → renderGuiItemDamage`、`Minecraft::respawnPlayer(int) → respawnPlayerById`、`Button` 的三个构造函数 → 构造函数 + `Button.at` / `Button.sized`。新遇到的照此命名，并补进这里。
- C++ 子类新增同名方法、遮蔽基类版本（`BedTile` 的无参 `setShape()`、`Spider::makeStepSound` 遮蔽同名字段）：改名或写成按参数分派的重载。

## R11 嵌套类型

`Biome::MobList`、`Tile::SoundType`、`ParticleType::Id` 等照原样写成 `Biome.MobList`：嵌套的类或类型放在文件顶层导出，再加一个同名、只含类型别名的 `declare namespace`；作值用时走类上的同名静态属性。写法见 `Biome.ts` 末尾。

## R12 未注册与未移植

- 未注册的具名方块、物品不是 `null`，而是访问即报错的哨兵（`Unregistered.ts`）。只拿来比较 id 的地方写 `=== idOf(Tile.xxx)`（未注册时得 −1），标 `ADAPTED(DeferredTile)`。
- 依赖未移植系统、暂时造不出来的对象用 `notPorted()`，同样访问即报错。

## R13 ES 模块循环与虚函数派发

- 基类需要 `new` 子类时：基类文件不 import 子类，由 `XInclude.ts` 注入；或把子类定义在基类文件里，原路径只做转出口（`ADAPTED(ESM)`）。注入用的钩子模块（如 `MobSpawnerHooks`）必须从包入口导出，否则注册不会执行。
- 两个只在运行时互相用到对方类的模块可以直接互相 import（例如 `OptionsScreen` 与 `CreditsScreen`）；`extends` 或模块顶层求值用到对方时才会出问题。
- **构造函数里的虚函数**：C++ 在基类构造期间只会调到正在构造的那个类的版本；JS 会派发到子类，而子类字段还没初始化。写成 `本类.prototype.方法.call(this, …)`。
- **非虚函数**：C++ 里没有 `virtual` 的同名函数（如 `Entity::_init`、`Mob::_init`、`Player::_init`）在 TS 里写成同名方法就变成了“虚”的。父类里调用它们时同样写 `本类.prototype.方法.call(this)`。
- 多重继承：纯接口性质的基类（`Container`）写成 TS 接口，默认实现写成函数；带状态的基类（`FillingContainer`）写成 mixin。
- C++ 的 `goto` 重启整个循环：写成带标签的 `for (;;) { for (…) { … continue label; } break; }`。

## R14 测试辅助

- `tests/helpers/headlessLevel.ts`：`createFlatLevel()` 后 `prepareLevel(level)` 得到真正的世界；`fakeLevel.ts`：只实现用到的接口的最小世界；`initTestTiles.ts`：按启动顺序注册方块。
- 建 `EntityRenderDispatcher`、任何模型之前先 `glSetContext(new GLES1(null))`（模型构造要 `glGenBuffers`）。
- 用 `Mth.sin` / `Mth.cos` 之前先 `Mth.initMth()`（查表在模块加载时全是 0）。

## 原版里容易被当成 bug 的事实

这些都已核实，照原样保留，**不要“修”**：

- 这一版一天是 **19200 刻**（16 分钟），不是 Java 版的 24000。
- 世界只有 256×256：`ChunkCache` 写死区块坐标 0–15，范围外是 `EmptyLevelChunk`（整块隐形基岩 95，高度图恒 0）。出生点从世界中心 (128, 128) 起找。
- `LevelChunk::ChunkBlockCount` 默认 0，由 `Minecraft::init` 设为 32768；世界单测必须先设。
- `TickNextTickData` 的去重永远不命中；`LightUpdate::update` 里的 `hasLast` 从不置 true；`DataLayer::setAll` 写的是 `br & (br << 4)`。
- `Tesselator` 的每个四边形输出 6 个顶点；`LevelRenderer` 构造时一次创建 26136 个 GL 缓冲。
- 游戏里的沙子是 `HeavyTile`，`SandTile` 类是死代码。物品 id 带 +256 偏移（`new SnowballItem(76)` 的 id 是 332）。
- `PARTICLETYPE(x)` 是逗号表达式，传给 `addParticle` 的是字符串 `"x"`。
- `ShapedRecipe::matches` 在这一版里几乎永远不成立（合成格对空格子返回空 `ItemInstance` 而不是 NULL）；触屏合成界面用的是材料计数，不受影响。
- `CommandManager::getCommand` 的判断写反了，所以 `/help <命令>` 总说 not found。
- 新 AI（`useNewAi`）、大树 `BasicTree`、`CommandGimmieItems`、大爆炸 / 水花粒子在原版里都没有启用或注册。

## 代码风格（2026-10-09 审核后统一）

- **文件头**：每个文件第一行写来源。对应 C++ 的写 `// 1:1 移植自 src/<路径>/X.h 与 X.cpp`，有暂缓或省略的语句时接着写“部分语句暂缓或省略，见文件内的 DEFERRED / OMIT 标记”；没有对应 C++ 文件的写 `// NEW：…` 或 `// ADAPTED(原因)：…`。
- **浮点截断**：文件顶部 `const f = Math.fround;`，正文一律写 `f(x)`，不直接写 `Math.fround(x)`（唯一例外是 `gles.ts`，那里已有名为 `f` 的局部变量）。
- **整数**：浮点转整数（C++ 的 `(int)x`）写 `Math.trunc(x)` 或 `f2i(x)`；32 位整数回绕（int 加减乘、`long` 只用低 32 位）写 `| 0` 与 `Math.imul`。两者对超出 int 范围的值结果不同，按 C++ 原句的意图选，不要互换。
- **重载**：按 R10。分派入口里可以按参数个数或 `typeof` 区分，但参数要有类型，不写 `...a: unknown[]` 再逐个强转。C++ 构造函数的重载没法改名：参数少的情形可以在构造函数里按参数个数区分，参数差别大的写成静态工厂（`Button.at`、`Button.sized`）。
- **类型逃逸**：不写 `as unknown as`，除非两边类型真的无关（例如模块循环迫使只能拿到结构类型）；写了就在旁边注明原因。父类到子类用普通的 `as 子类`。C++ 里“声明了但不用”的成员写成 `protected`（不触发未使用告警），不要用 `void (X.prototype as unknown as …)` 压告警。
- **可见性**：跟 C++ 一致。C++ 子类把基类的 protected 函数重新声明成 public 的，TS 子类同样写成 public。
- **格式**：Prettier（`pnpm format`）。全仓库格式化的提交记在 `.git-blame-ignore-revs` 里。
