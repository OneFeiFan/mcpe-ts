# 全量审核方案（严格版）

本文件是继续“逐函数全量审核”的**唯一依据**。目标：TS 代码的**行为**与参考 C++ 逐位一致（数值、顺序、随机数、存档、画面）。审核者（人或 AI）必须严格按本文件执行；本文件没有覆盖到的情况，按“第 9 节 拿不准时”处理，**不要猜**。

已完成：第 1 批（util、nbt、platform），第 2 批第一部分（Vec3、AABB、Entity.move、ItemEntity.tick、Throwable.shoot 等）。记录在 `docs/审核记录/`，范围与进度见 `docs/审核记录/待审清单.md`。

---

## 1. 原则

1. **以参考 C++ 为唯一标准**，不以“看起来合理”“JS 习惯”为标准。C++ 写什么，TS 就做什么。
2. **原版的怪癖照抄**（写反的判断、多余的调用、奇怪的常量、不更新的字段），在代码旁注明“怪癖保留”，并记入审核记录。
3. **原版的未定义行为不复刻**（越界、读未初始化内存、空指针、负长度 `new[]`）：改成安全写法（返回 0 / null / 抛错），标 `ADAPTED(Safety)` 并写明 C++ 原句。未初始化的成员取 0 / false / null 并注明。
4. **有意的偏离**（浏览器平台、ES 模块加载顺序、联机暂缓）必须标 `ADAPTED(原因)` / `DEFERRED(系统)` / `OMIT(系统)`，写明 C++ 原句或签名。没有标记的偏离一律视为错误。
5. **只改审核发现的问题**。不做与审核无关的重构、改名、“顺手优化”。
6. **一次只审一个文件**；一个文件审完（工作表全部填完、问题全部修完、验证全部通过、记录写完、提交）再开始下一个。

## 4. 单个文件的审核流程（必须逐步执行）

**第 1 步：生成工作表。**
`python tools/audit/worksheet.py $REF <TS 文件> > /tmp/<名>.ws.md`。工作表列出 C++ 的每个成员函数（含每个重载）、对应的 TS 方法与行号、函数体相似度，以及“C++ 有、TS 没有”“TS 有、C++ 没有”两张清单。**工作表里的每一行都必须有结论，不允许空着。** 工作表按名字（含 R10 改名后的前缀）自动配对，可能配错（例如 C++ 的 `distanceTo` 配到了 TS 的 `distanceToSqr`、`init()` 配到 `initScreen` 是对的），以人工核对为准；构造函数的多个重载都配到 TS 的 `constructor`，要逐个确认分派是否正确。

**第 2 步：读 C++。** 同时读 `.h`（成员声明、默认参数、`virtual`、内联函数、成员初始化顺序、类型）与 `.cpp`。记下：每个成员的**类型**（float / double / int / short / char / unsigned / long / long long / bool）、哪些函数是 `virtual`、构造函数初始化列表、没有初始化的成员。

**第 3 步：逐个函数并排对照**，按第 5 节的清单逐项检查，**每一行 C++ 都要在 TS 里找到对应**（或明确的 ADAPTED / DEFERRED / OMIT 标记）。相似度高的函数也必须逐行看——相似度只是提示。

**第 4 步：给每个函数下结论**，填进工作表：

| 结论                    | 含义                                                       |
| ----------------------- | ---------------------------------------------------------- |
| 一致                    | 逐行核对过，行为相同                                       |
| 怪癖保留                | 原版的奇怪行为，TS 照抄并有注释                            |
| 已修（编号）            | 发现移植错误并已修正                                       |
| 原版 bug                | C++ 本身的错误、照抄了；登记在记录里，以后由用户决定修不修 |
| ADAPTED（理由）         | 有意偏离，代码里有标记                                     |
| OMIT / DEFERRED（理由） | 不移植 / 暂缓，代码里有标记                                |

**第 5 步：修复。** 每个“已修”都要有验证：

- 能写单元测试的写单元测试（放在 `tests/unit/<包>/`，测试名写明审核编号）；
- 数值或顺序问题优先用**黄金样本**验证（第 7 节）；已有黄金样本覆盖的，尽量把容差收紧为逐位；
- 修复前先确认测试会失败（撤掉修复跑一次），修复后通过。

**第 6 步：验证。** `pnpm typecheck` 0 错误；三批测试全部通过；`npx prettier --check` 通过改过的文件；`pnpm ledger` 的变化能逐条解释。

**第 7 步：记录。** 在 `docs/审核记录/<模块>.md` 追加该文件的结论表（格式见第 8 节），更新 `docs/审核记录/README.md` 与 `待审清单.md` 的进度。

**第 8 步：提交。** 一个文件一个提交（大文件可按函数组分几个提交），提交说明格式见第 8 节。

## 5. 检查清单（逐函数逐项）

### 5.1 数值：float 与整数

1. **字段类型**：C++ 的 `float` 字段在 TS 里每次赋值都要 `f()`（`const f = Math.fround;`）；`double` 字段不包；`int` 字段用 `| 0`（溢出回绕）或保证结果是整数；`short` 用 `(v << 16) >> 16`；`char`（x86 上有符号）用 `(v << 24) >> 24`；`unsigned char` 用 `& 0xff`；`unsigned int` 用 `>>> 0`。
2. **形参类型**：C++ 形参是 `float` 的，函数开头先把实参转成 float（`x = f(x)`）。TS 调用方可能传入 double，C++ 里会被舍入——**这是本次审核发现最多的一类错误**。
3. **每一步运算都舍入**：float 的 `a * b + c` 写成 `f(f(a * b) + c)`。整段用 double 算、最后才 `f()` 是错的。
4. **结合顺序**：C++ 的 `a + b + c` 是 `(a + b) + c`，`a * b * c` 是 `(a * b) * c`。TS 必须按同样顺序嵌套：`f(f(a + b) + c)`，不能写成 `f(a + f(b + c))`。`g * 0.0075f * u` 是 `(g * 0.0075f) * u`。
5. **复合赋值**：`x *= a * b` 是 `x = x * (a * b)`（先算右边）；`x += y * z` 是 `x = x + (y * z)`。
6. **常量**：C++ 原文带 `f` 后缀的常量（`0.98f`）写成 `f(0.98)`；不带后缀的是 double 常量，不要包。`0.6f * 0.98f` 这类常量表达式在 C++ 里按 float 算：`f(f(0.6) * f(0.98))`。
7. **int 与 float 混算**：int 先转 float 再算（`f(i) * x`）；float 赋给 int 是 `(int)` 截断——用 `f2i(x)`（越界或 NaN 得 -2147483648，与 x86 相同），不要用 `Math.floor`。
8. **整数运算**：int 乘法用 `Math.imul`；加减后 `| 0`；整数除法 `Math.trunc(a / b)`（用 `python tools/porting/divs.py <文件>` 检查）；`%` 的符号与 C++ 相同（向零）。移位：`>>` 有符号、`>>>` 对应无符号。
9. **数学函数**：
   - `Mth::sin` / `Mth::cos` 是查表，必须用 `Mth.sin` / `Mth.cos`；
   - 不带 `Mth::` 的 `sin`、`cos`、`sqrt`、`pow`、`atan2`、`log`、`fabs`、`floor`（C 库）按 **double** 算，结果存回 float 时再 `f()`；
   - `std::sqrt(float)`、`std::log(float)` 等带 `std::` 的是 **float** 重载：每一步 `f()`；
   - 不带 `Mth::` 的 `abs(float)` 是 float 版（已由黄金样本确认）；
   - `Mth.floor`、`Mth.sqrt` 等已按 C++ 实现（float 形参），直接调用即可。
10. **NaN 与 ±0**：`Mth.Min` / `Mth.Max` / `Mth.abs` 已按 C++ 的比较写法实现；**不要**换成 `Math.min` / `Math.max` / `Math.abs`（在 NaN、±0 上结果不同）。`Vec3` 的构造函数会把 -0 变成 +0。
11. **`long` 的宽度**：x86-64 Linux（黄金样本的生成环境）上 `long` 是 64 位；`long long` 64 位。用到 64 位的地方用 BigInt 或拆成高低 32 位，并注明。依赖溢出的地方以黄金样本（x86-64）为准。
12. **字符串与数字的格式**：`ss << floatValue` 与 `%g` 用 `formatG`（`@mcpe/util`）；`%d`、`%.3f` 等按 printf 的规则（`toFixed` 在恰好一半时与 printf 可能不同，要求严格时自己实现）。

### 5.2 结构：继承、虚函数、重载

13. **非虚函数**：C++ 没有 `virtual`（也没有从基类继承 `virtual`）的函数，在 TS 里写成同名方法会变成“虚”的。逐个检查**每个调用点在 C++ 里的静态类型**：如果通过基类指针调用、而子类有同名方法，C++ 调的是基类版本——TS 必须写成 `基类.prototype.方法.call(obj, …)`。（实例：`TileEntity::setRemoved`、`Entity::_init`。）
14. **构造函数里的虚调用**：C++ 在基类构造期间只会调到基类的版本。TS 写成 `本类.prototype.方法.call(this, …)`。
15. **虚函数的默认参数**：C++ 的默认参数按**静态类型**取（基类声明的默认值），而不是子类重写里写的默认值。检查重写方法有没有不同的默认值。
16. **重载**：按 R10（`docs/移植规范.md`）。C++ 按实参的**静态类型**选重载（int / float / char / 指针 / 引用）；TS 的分派必须能区分出相同的那一个。合并成“一个方法 + 默认参数”的，必须确认短的重载只是用常量转调长的那个。
17. **遮蔽**：子类定义了与基类**字段**或**非虚函数**同名的成员——C++ 两者并存，TS 会互相覆盖，必须改名并注明。
18. **`super::` 调用**：确认 TS 的 `super.方法()` 调的是 C++ 指定的那一层（C++ 可能写 `Mob::tick()` 跳过中间层）。
19. **成员初始化顺序**：按 C++ 成员声明顺序初始化（初始化列表的写法顺序不算）；字段初始化器里不能调用依赖子类的东西。
20. **可见性**：与 C++ 一致（子类把 protected 重新声明成 public 的，TS 子类也写 public）。

### 5.3 值语义与容器

21. **按值**：C++ 按值传入、按值返回、按值存成员的 `Vec3`、`AABB`、`ItemInstance`、`TilePos`、`Pos`、`HitResult`、结构体：TS 赋值时必须复制（`new X(…)`、`copy()`、`setFrom()`）。按引用（`&`）传入并被修改的是输出参数，TS 用返回值或可变对象实现，注明。
22. **`std::map` / `std::set`**：按键**有序**遍历（字符串按字节序）；`insert` 遇到已有的键**不覆盖**；`operator[]` 读一个不存在的键会**插入默认值**；`find` 后 `erase`。JS `Map` 是插入顺序，遍历前要排序。
23. **`std::vector` 的 `erase`**：边遍历边删时下标的调整要与 C++ 相同（`splice(i, 1); i--`）。
24. **排序**：`std::sort` **不稳定**，JS 的 `Array.prototype.sort` 稳定。比较函数有相等的元素、且顺序会影响结果时，必须注明并用黄金样本确认（必要时照 libstdc++ 的 introsort 实现）。`std::stable_sort` 对应 JS 的 sort。
25. **哈希容器**（`std::unordered_map` 等）的遍历顺序依赖实现：如果遍历顺序影响结果，标出来并用黄金样本确认。

### 5.4 随机数与求值顺序

26. **随机源**：确认用的是哪个 `Random` 实例（成员 `random`、`sharedRandom`、`Mth::random` 的模块级实例、`level->random`）。不能合并、不能替换。
27. **取数顺序**：与 C++ 语句顺序完全一致；`for` 循环展开后顺序不变；**短路求值**（`&&`、`||`、`?:`）会跳过某些随机数调用，TS 必须同样短路。
28. **函数实参的求值顺序在 C++ 里是未指定的**：一条语句里的多个实参都调用随机数（`foo(random.nextFloat(), random.nextFloat())`）时，GCC 的实际顺序必须用黄金样本确认，确认后在 TS 里显式按该顺序取数并注明。
29. **空的 `if` 分支、被注释掉的调用**：如果条件里调用了随机数，条件本身要保留（例如被注释掉的大树留下的 `if (random.nextInt(10) == 0) {}`）。

### 5.5 其他

30. **字符串**：C++ `std::string` 是字节；TS 是 UTF-16。长度、截断、比较、哈希涉及非 ASCII 时要按 UTF-8 字节处理（`hashCode`、`compareStdString` 已有实现）。
31. **char 的符号**：`char` 在 x86 上有符号；`readByte` 已返回 -128..127。
32. **布尔转整数、整数转布尔**：`(int)bool` 是 0/1；`if (int)` 是非 0。
33. **日志**：`LOGI` / `printf` 的文字要与 C++ 一致（运行对比会逐行比较日志，见 `tools/original/compare/logdiff.py`）。
34. **DEFERRED / OMIT 标记**：逐条确认仍然成立；已经可以移植的要移植并删掉标记。
35. **注释与文件头**：与代码一致；发现过时、错误的注释（例如声称“C++ 这里没有……”）要核对后改正。

## 6. 绝对禁止

- 修改 `fixtures/golden/` 下的任何文件（只能用 `tools/golden/build.sh` 从 C++ 重新生成）；修改参考 C++。
- 为了让测试通过而放宽断言、加 `.skip` / `.only`、删测试、改期望值（除非能证明期望值本身来自 TS 而不是 C++，并在提交说明里写明）。
- “修正”原版的怪癖或 bug（除非用户明确要求）。
- 用 double 计算 C++ 里是 float 的值；用 `Math.min/max/abs/floor` 代替 `Mth` 里的同名函数。
- 用 `as unknown as`、`any`、`@ts-ignore` 绕过类型检查来“让它能跑”。
- 一次提交混入多个文件的无关修改；提交未通过验证的代码。
- 拿不准时自行决定——必须按第 9 节处理。

## 7. 黄金样本

数值与顺序问题的最终裁判是黄金样本（从参考 C++ 跑出来的标准答案）。

- 现有样本：`tools/golden/harness_*.cpp` → `fixtures/golden/*.json` → `tests/golden/*.golden.test.ts`。清单与生成方法见 `docs/验证方法.md`。

- **样本必须能分辨你关心的那个细节**：写完后故意改坏 TS 实现，确认测试会失败。

- 已有样本用了容差的，审核到相关代码时尝试收紧为逐位（G12-2 碰撞样本就是这样收紧的）。

## 10. 示例：一次完整的单函数审核

C++（`Throwable.cpp`）：

```cpp
void Throwable::shoot(float xd, float yd, float zd, float pow, float uncertainty) {
  float dist = Mth::sqrt(xd * xd + yd * yd + zd * zd);
  ...
  xd += (sharedRandom.nextGaussian()) * 0.0075f * uncertainty;
```

审核前的 TS：

```ts
shoot(xd_: number, yd_: number, zd_: number, pow: number, uncertainty: number): void {
  let xd = xd_;                                                          // ✗ 形参没有先转 float
```
