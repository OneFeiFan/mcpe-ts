进度修正包改了什么（第 2 版）

  • BiomeSource（种子链，影响最大）：① downfalls、noises 初值写成了长度 0 的数组，PerlinNoise 只在缓冲区为 null 时才分配，结果降水、噪声全部取不到值，256 列的群系全是空；改回 C++ 的 NULL。② 每列温度、降水按 double 计算，改成逐步 float（与 C++ 的 1.1f、0.15f 等常量一致）。③ 种子乘法改成 Math.imul(seed | 0, 9871)，否则 64 位种子会超出 2^53。现在 4 个种子（含 64 位）× 7 组数据与 C++ 逐位一致。

  • ADAPTED 接缝是 6 处而不是 3 处：GameRenderer::tick 在没有 player 时直接返回，fogBr 永远是 0，天空和雾会全黑；鼠标平滑量也在这里算。

D1 基准
分支源码 + 分支默认选项，不改任何选项。桌面输入由平台“无触屏”自动选中。
D2 构建开关

R1 路径与包

  • 镜像 C++：src/world/level/tile/Tile.h → packages/world/src/level/tile/Tile.ts，类名、文件名不改（仓库里 Pos、TilePos、ChunkPos、material、phys 已经这样做）。
  • 依赖只能向右：platform → util → core → world → client → apps/web。world 不得依赖 client 与 DOM。

R2 文件类别与标记

  • 1:1：逐函数照抄，只允许 TS 语法层面的机械改写（重载 → 参数分派、运算符 → equals/lessThan、按值 → clone）。
  • 1:1 + OMIT / DEFERRED：同上，但缺口全部登记。ADAPTED：有意偏离 C++，每处写明原因。NEW：C++ 里没有的文件。

  • 每个函数只能是 PORT、PORT-CUT、OMIT 之一，不写桩函数体。
  • virtual 函数在整个继承链上一起 OMIT；被 OMIT 的函数若有已移植代码调用，在调用处标 DEFERRED。
  • 析构函数不移植；未被 D2 选中的 #if 分支不移植也不登记。
  • 必须存在、但唯一的实现依赖未移植系统的函数（例如 Dimension::createRandomLevelSource）：保留签名，原句写成 DEFERRED，函数体抛出写明原因的错误，不返回假值。
  • C++ 构造函数没有初始化的字段（未定义值）取 0 或 false，并在字段旁注明。

R10 C++ 重载的 virtual

  • 同名方法在 TS 里只能有一个实现。按两种情形处理（修订版 8 起不再用 $n 后缀）：情形 A——短的重载只是用常量转调长的那个（且没有子类单独重写短的），合并成一个带默认参数或可选参数的方法，例如 spawnResources(level, x, y, z, data, odds = 1)、saveLevelData(levelData, players?)；情形 B——其余情况，基类保留原名作为分派入口（TS 重载签名，调用处与 C++ 完全一样），每个 C++ 重载对应一个按区分参数命名的实现方法，子类重写 C++ 的哪个重载，就重写对应的实现方法；分派入口本身不要在子类里重写。现有的对照：getTexture → getTextureForFace / getTextureForData / getTextureAt；mayPlace → mayPlaceAt / mayPlaceOnFace；mayPick → mayPickBasic / mayPickWithData；getSignal → getSignalAt / getSignalInDirection；useOn → useOnWithoutPlayer / useOnByPlayer；getDescriptionId、getDescription → …ForItem / …ForInstance；getIcon → getIconForAux / getIconForInstance；getRegion → getRegion3D / getRegion2D；App、Dimension 的无参 init() → initApp、initDimension；onGraphicsReset() → onAppGraphicsReset；（S12 起）Player::interact(Entity*) → interactWith、静态的 Player::animateRespawn(Player*, Level*) → animateRespawnFor、Inventory::removeItem(const ItemInstance*) → removeItemInstance、Mob::checkDespawn(Mob*) → checkDespawnFrom、FillingContainer::save/load(ListTag*) → saveItems / loadItems（与 TileEntity 的同名函数在同一原型链上）、Level::tick(Entity*[, bool]) → tickEntity(e, actual = true)、LevelRenderer::render(const AABB&) → renderAABB、SynchedEntityData 的模板 define<T>、set → defineByte、setShort……（按类型拆开）、ItemRenderer::renderGuiItem(…, w, h, fancy) → renderGuiItemSized、renderGuiItemDecorations(item, x, y) → renderGuiItemDamage；（S13 起）Screen::init()（子类重写的无参版本）→ initScreen、EntityRenderer::render(const AABB&, …) → renderAABB、EntityRenderDispatcher::render(entity, x, y, z, rot, a) → renderAt、getRenderer(EntityRendererId) → getRendererById、Button 的三个构造函数 → 构造函数 + Button.at / Button.sized；引用参数改为返回元组：Gui::getSlotPos、Screen::toGUICoordinate、ScrollingPane::getGridItemFor_slow、queryHoldTime。新遇到的重载照此命名并补进这份对照。
  • 参数个数相同、只靠 int / float / char 区分的 C++ 重载（JS 分不出来）：最常用的一种保留原名，其余改名并标 ADAPTED(Cpp)。已用于 Tesselator 的 color：float 版仍叫 color(r, g, b[, a])，int 版是 colorInt，char 版是 colorChar；color(int c)、color(int c, int alpha) 参数个数不同，保留原名。Options 的三个 set 合成一个，按选项本身的类型设值。
  • C++ 子类新增同名方法、遮蔽基类版本的情况（BedTile 的无参 setShape()）：写成同一方法的两个重载，按参数分派，有参时转给 super。

R11 C++ 的嵌套类型

  • Biome::MobList、Tile::SoundType、ParticleType::Id 等，在 TS 里照原样写成 Biome.MobList：嵌套的类或类型放在文件顶层导出，再加一个同名、只含类型别名的 declare namespace（编译后不产生代码）；作值用时走类上的同名静态属性。写法见 Biome.ts 末尾。

R12 未注册与未移植

  • DEFERRED 的具名方块、物品、群系不是 null，而是访问即报错的哨兵（Unregistered.ts），报错写明字段名；分支里没有任何地方判断它们是否为 NULL，所以不改变行为。
  • 只拿来比较 id 的地方写 === idOf(Tile.xxx)，标 ADAPTED(DeferredTile)：未注册时返回 −1，按“不相等”处理。把 id 写进世界、读纹理等其他用途仍直接写 .id。
  • 依赖未移植系统、暂时造不出来的对象用 notPorted()，同样访问即报错。
  • 测试里用 isUnregistered(x) 判断，不会触发哨兵。

R13 ES 模块循环

  • 基类需要 new 子类（注册表、工厂）时：基类文件不 import 子类，由 XInclude.ts 注入（R7）；或像 NormalDayCycleDimension 那样把子类定义在基类文件里，原路径的文件只做转出口（ADAPTED(ESM)）。
  • 方块类只 import { Tile } from './Tile'，不经入口文件。

修订版 9 新增的约定（S11–S12 中发现）

  • 构造函数里的虚函数（ADAPTED(Cpp)）：C++ 在基类构造期间调用虚函数，只会调到正在构造的那个类的版本；JS 会派发到子类，而子类的字段此时还没初始化。凡是构造函数里调用了会被子类重写的方法，一律写成 本类.prototype.方法.call(this, …)（Entity、Mob、Player 的 _init、getMaxHealth）。
  • 多重继承（ADAPTED(Cpp)）：纯接口性质的基类（如 Container）写成 TS 接口，默认实现写成函数；带状态和实现的基类（如 FillingContainer）写成 mixin：FillingContainerMixin(Base)，构造参数经 initFillingContainer(...) 传入。同名函数在合并后的原型链上会互相遮蔽，按 R10 改名。
  • 基类不要 import 子类（ES 模块循环会触发 “Class extends value undefined”）：需要在基类里 new 子类时用注入——TileInclude、ItemInclude、TagInclude、TileEntityInclude、registerItemEntityClass。
  • 暂未注册的方块：只做 id 比较时用 idOf(Tile.x)（未注册得 −1）；注册后改回 .id。
  • 不要用 declare 代替 import：declare function f() 能通过类型检查，但运行时不存在。
  • C++ 的未定义行为（读未初始化的成员、把未初始化的成员传给基类）不复刻，黄金样本里标 uninit，不比较。
  • C++ 成员的构造顺序：C++ 按成员声明顺序构造（如 Minecraft 的 options 在 gui 之前）。TS 的字段初始化器若依赖别的字段，改到构造函数里按 C++ 的顺序创建（Minecraft.gui、screenChooser）。
  • 纹理必须预加载：网页版的 loadTexture 只从启动时的预加载表取。漏了一张时，绑定失败、沿用上一次绑定的纹理，表现为“画错了图”（S13 的左上角残影就是暗角画成了 icons.png）。新代码用到新纹理时同步加进 apps/web/src/assets.ts。
  • 按值语义：C++ 按值存放的 ItemInstance、Pos、结构体，赋值时复制（new ItemInstance(x)、dst.init(id, count, aux)），不要共享引用。
