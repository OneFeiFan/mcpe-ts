## 换会话流程（以后照这个做）

**什么时候换**：满足任一条就准备换——

- `/context` 显示上下文占用超过约 60%；
- 当前会话的 `.jsonl` 记录超过约 100 MB；
- 连续出现 502/超时且重试无效。

**换之前**：

1. 收尾手头工作：能提交的提交；没做完的把状态写进本文件。
2. 更新本文件的“当前状态 / 未提交的改动 / 接下来做什么”。
3. 跑一次 `pnpm check`，确认没有遗留报错。
4. `git commit`（代码和文档一起）。
5. 关掉旧会话，开新会话。

**新会话开场**：先读 `CLAUDE.md` → 本文件 → `docs/审核记录/待审清单.md`，然后从“接下来做什么”继续。

**要丢掉的东西**：

- 旧会话的原始工具输出、思考过程、重试日志——不搬。
- 临时提取文件（如 `%TEMP%\mcpe-handoff\extract.md`）——交接完成后删除。
- 旧会话的 `.jsonl` 记录——确认新会话正常后，可删除或归档（删除不可恢复，先确认）。
